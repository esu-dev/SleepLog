======================================================================
睡眠時間記録iOSアプリ（Sleep Log）詳細開発仕様書
======================================================================
[プロジェクト構成]
- メインフレームワーク: React Native (Expo SDK)
- 開発環境: Windows (実機確認: iPhone Expo Go)
- 言語: TypeScript
- スタイリング: NativeWind (Tailwind CSS)
- データベース: expo-sqlite (ローカル完結)
- 状態管理: Zustand
- フォーム管理: React Hook Form + Zod

----------------------------------------------------------------------
1. アプリ概要
----------------------------------------------------------------------
本アプリは、Windows環境においてExpo Go（iPhone）を使用して開発する、ローカル
完結型の睡眠時間記録アプリである。
「寝る前にボタンを押し、起きたら止める」という直感的なリアルタイム計測を
コア機能とし、押し忘れた場合の過去データ手動入力、履歴の一覧表示、および
直近1週間の統計グラフ表示を提供する。外部サーバーへの通信は行わず、すべての
データは端末内のSQLiteに安全に保存される。

----------------------------------------------------------------------
2. データベース設計 (expo-sqlite)
----------------------------------------------------------------------
■ テーブル名: sleep_logs
端末ローカルのSQLiteデータベース内に作成する。日時はタイムゾーンの問題を
防ぐため、一貫して「ISO8601形式の文字列（UTCまたはJST固定）」で保存する。

[カラム定義]
- id         : INTEGER / PRIMARY KEY AUTOINCREMENT (自動採番)
- bedtime    : TEXT (ISO8601形式) / 必須 / 就寝時刻
- wake_time  : TEXT (ISO8601形式) / 必須 / 起床時刻
- duration   : INTEGER / 必須 / 睡眠時間（秒単位）
- memo       : TEXT / 任意 / 備考・メモ（最大100文字）

----------------------------------------------------------------------
3. 実装段階別仕様
----------------------------------------------------------------------

■■ Phase 1: 開発基盤・DB・状態管理の構築 ■■
最優先でアプリのデータ骨組みと状態管理レイヤーを構築する。UIは標準コンポー
ネントのみで構成し、ログ出力を用いて動作検証を行う。

1.1 データベース初期化
  - ファイル配置: `/src/db/client.ts`
  - アプリ起動時、`openDatabaseSync('sleep_app.db')` を実行。
  - `sleep_logs` テーブルが存在しない場合、`CREATE TABLE IF NOT EXISTS` 
    クエリを走らせて自動生成する。

1.2 グローバル状態管理
  - ファイル配置: `/src/store/useSleepStore.ts`
  - Zustandを用いて、アプリが現在「計測中か否か」および「開始時刻」を管理。
  - アプリが強制終了やバックグラウンド移行されても状態を維持するため、
    Zustandの `persist` ミドルウェアを適用してローカルストレージへ自動同期。
  [状態定義]
    - isTracking: boolean (計測中フラグ)
    - startTime: string | null (就寝時刻のISO文字列)
    - startSleep(): void (計測開始処理)
    - wakeUp(): void (計測終了・ストアクリア処理)
    - resetTracking(): void (強制リセット処理)


■■ Phase 2: コア機能の実装 (リアルタイム計測・手動入力) ■■
実際にデータをDBへ永続化し、Zodによるバリデーション処理を実装する。

2.1 リアルタイム計測画面 (Home)
  - 待機状態UI: 「おやすみなさい」ボタンを表示。
  - 計測状態UI: 「おはようございます」ボタンを表示。また、`setInterval` を
    用いて1秒ごとに現在の経過時間（HH:MM:SS）をリアルタイム計算して描画。
  - 計測終了フロー:
    1. 「おはよう」タップ時、現在時刻を `wake_time` として取得。
    2. ストアの `startTime` との差分を計算し、秒単位で `duration` を算出。
    3. SQLiteへ `INSERT` クエリを発行しデータを保存。
    4. ストアの計測状態をリセットする。

2.2 手動入力フォーム (Add Log)
  - 押し忘れた過去のデータを後からカレンダー・時刻セレクターで入力する画面。
  - `React Hook Form` と `Zod` を組み合わせて実装。
  - バリデーションスキーマ (`/src/schemas/sleepSchema.ts`):
    - bedtime: 必須項目
    - wake_time: 必須項目
    - カスタム検証: `wake_time` は必ず `bedtime` より未来の時刻であること。
    - カスタム検証: 総睡眠時間（`duration`）が24時間を超える場合はエラー。
    - memo: 任意項目（最大100文字）。


■■ Phase 3: 履歴表示と統計の可視化 ■■
蓄積されたデータをユーザーが閲覧・分析できる画面を実装する。

3.1 履歴リスト画面 (History)
  - Shopifyの `@shopify/flash-list` を採用し、Expo Go上でも滑らかに高速
    スクロールができるよう最適化。
  - SQLiteから `SELECT * FROM sleep_logs ORDER BY bedtime DESC` でデータを
    取得し、各カードに「日付」「睡眠時間（○時間○分）」「メモ」を表示。
  - 各カードに削除ボタン、またはスワイプアクションを配置し、特定の `id` を
    対象とした `DELETE` クエリを実行可能にする。

3.2 統計チャート画面 (Stats)
  - JS/SVGベースで動作する `react-native-gifted-charts` または 
    `react-native-svg` を採用（Windows + Expo Go環境でネイティブエラーを
    防ぐため）。
  - 直近7日間の睡眠データをSQLiteから取得（またはJS側で直近7日分にマッピ
    ング）し、日ごとの睡眠時間を棒グラフ（バーチャート）として描画。
  - 直近7日間の「平均睡眠時間」を算出して画面上部にハイライト表示する。


■■ Phase 4: UI/UXのブラッシュアップと調整 ■■
NativeWindを用いたスタイリングの適用と、例外系のハンドリングを行う。

4.1 スタイリング (NativeWind / Tailwind CSS)
  - 就寝前や起床直後の暗い部屋でも目に優しいよう、ディープネイビーや
    ダークスレート（例: `bg-slate-900`, `text-slate-100`）を基調とした
    ダークモード風のカラーパレットを標準採用。
  - ボタン等のタップ領域はアクセシビリティを考慮し、44x44dp以上を確保。
  - `active:scale-95` などのユーティリティクラスを利用し、心地よいタップ
    フィードバック（アニメーション）を実装。

4.2 例外・エラーハンドリング
  - 二重計測防止: タイマー計測中は、手動入力画面への遷移を制限または
    フォームを非活性化する。
  - 空ステート（Empty State）への対応: データベースのレコードが0件の場合、
    「データがありません。今夜から記録を始めましょう！」などの案内文を
    表示するプレースホルダー画面を実装。

----------------------------------------------------------------------
4. 開発における注意点・Tips（Windows + Expo Go）
----------------------------------------------------------------------
1. タイムゾーンの取り扱い:
   JavaScriptの `Date` オブジェクトはローカル環境に依存するため、DBへの保存
   時は一貫してUTC（またはタイムゾーン情報付きのISO文字列）で行い、画面に
   表示する際のみユーザーのローカル時間に変換するヘルパー関数
   （`/src/utils/date.ts`）を用意すること。
2. 型の共通化:
   Zodスキーマから推論した型（`z.infer<typeof sleepSchema>`）を、React Hook Form
   のコンテキストや、SQLiteのインサート処理の引数型と適合させることで、
   TypeScriptの型安全性を最大限活かし、型定義の二重管理を防ぐ。
3. 実機テストの効率化:
   SQLiteのデータ状態をリセットするための「開発用データ全削除ボタン」を、
   開発環境時のみ設定画面等に非公式に配置しておくと、テストがスムーズになる。
